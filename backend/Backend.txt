Backend — Node.js + Express (depuis le 19/11, la stack Python/FastAPI est abandonnée).

Rôle : lire un Rapport des Possibles (PDF) déjà rangé dans notre base, en
extraire les scores des graphiques et les métiers sous forme de JSON avec
leurs sources, et plus tard dialoguer avec une IA et générer des
restitutions personnalisées (texte, audio, fiches interactives).

Lancer :
    cd backend
    npm install
    npm start          # API sur http://localhost:8000
    npm test           # tests sur les rapports de prive/ (sautés si prive/ est vide)
    npm run lien -- rapport.pdf   # crée le jeton du lien à envoyer par mail
    npm run resume -- rapport.pdf # essai du résumé écrit dans le terminal (modèle du .env)

IA : Ollama en local. Le modèle se règle dans backend/.env (OLLAMA_MODEL,
voir .env.example) ; sans modèle, le résumé est construit sans IA à partir
des mêmes faits (repli). Les tests n'appellent jamais Ollama.

Audio : Piper en local (PIPER_BIN, PIPER_MODELE dans backend/.env). Sans voix
réglée, pas d'audio : le front affiche le texte seul. Les tests utilisent un
faux Piper (tests/outils/fauxPiper.js). Installation sur le PC de démo, hors
du dépôt :
    - le binaire Piper (archive « piper_linux_x86_64 » des versions de
      github.com/rhasspy/piper), décompressé par exemple dans ~/piper/ ;
    - une voix française .onnx et son .onnx.json (dépôt « rhasspy/piper-voices »,
      dossier fr/fr_FR), à côté ; vérifier la licence de la voix choisie ;
    - essai : echo "Bonjour" | ~/piper/piper --model <voix>.onnx --output_file essai.wav
    - puis PIPER_BIN=~/piper/piper et PIPER_MODELE=<chemin de la voix>.onnx.

Accès : pas d'authentification. Le jeune ouvre sa page depuis un lien reçu
par mail, qui porte un jeton aléatoire (32 caractères hexadécimaux). Pour
l'instant, la « base » est le dossier prive/ (ignoré par git) : les PDF, et
prive/liens.json, la table jeton -> fichier écrite par `npm run lien`.
Le jeton est la seule clé : ne jamais le dériver du numéro de rapport, ne
jamais ajouter de route qui liste les rapports ou les jetons.

Routes actuelles :
    GET  /report/{jeton}        : analyse complète (JSON avec sources), calculée à la
                                  première consultation puis relue depuis storage/outputs/
                                  Contient rapport_pdf_url = /report/{jeton}/pdf (relative à l'API).
    GET  /report/{jeton}/scores : les 3 graphiques (RIASEC, aptitudes, HEXACO) avec leurs sources
    GET  /report/{jeton}/pdf    : le PDF, pour la visionneuse (PDF.js / react-pdf). Nom neutre
                                  « rapport.pdf », lecture par morceaux (Range, 206) et en-têtes
                                  Content-Range… exposés en CORS.
    POST /report/{jeton}/resume : résumé écrit, corps facultatif { onboarding } (forme du contrat).
                                  Renvoie points [{ texte, page, fait, origine }], texte, phrases,
                                  faits [{ id, page, texte }], genere_par { mode, modele, raison },
                                  controle { phrases_refusees, raisons }, choix_pris_en_compte.
                                  Mis en cache par jeton, choix et modèle (sauf en repli complet).
                                  Plus audio_url (/report/{jeton}/audio/{empreinte}) si une voix
                                  est réglée, sinon null.
    GET  /report/{jeton}/audio/{empreinte} : le texte du résumé lu par Piper (audio/wav), créé au
                                  premier appel puis gardé en cache ; 503 si pas de voix réglée
                                  ou si Piper échoue (le front garde alors le texte seul).
    Jeton mal formé ou inconnu : 404 « Rapport introuvable », toujours la même réponse.
    Réponses en Cache-Control: no-store et Referrer-Policy: no-referrer (données personnelles).
