NOTE POUR LA DÉMO — ce que le travail backend de Julien change pour les autres
==============================================================================
Branches : julien/chatbot (assistant /chat), julien/liens-metiers-base (base des
liens, mails, liens des pages métier). Pas encore fusionnées dans Backend.
Fichier public comme tout le dépôt : aucun nom de rapport, aucune valeur réelle.


1. POUR TOUTE L'ÉQUIPE
----------------------
- Node 22.13 ou plus récent est OBLIGATOIRE pour le backend (base SQLite
  node:sqlite). Avec Node 20, l'API ne démarre plus. Vérifier : node --version
  (le site demande déjà Node 22.16, donc une seule version suffit).
- Au démarrage de l'API, l'avertissement « ExperimentalWarning: SQLite is an
  experimental feature » est normal.
- Les liens sont maintenant dans prive/possibles.db (ignoré par git).
  prive/liens.json n'est pas modifié : les jetons déjà créés marchent toujours.
- Un lien expire au bout d'un an. Un lien expiré ou révoqué reçoit le même 404
  qu'un jeton inconnu.


2. POUR LE FRONT
----------------
a) L'assistant (src/components/Assistant.jsx affiche encore une réponse d'exemple)
   POST <VITE_API_URL>/chat/<jeton>
   Corps : {
     "question": "Pourquoi ces métiers ?",            (500 caractères au plus)
     "historique": [{ "de": "moi" | "ia", "texte": "…" }],   (les 6 derniers suffisent)
     "onboarding": { … }                              (même bloc que pour le résumé)
   }
   Réponse : {
     "reponse": "texte à afficher",
     "sources": [{ "fait": "f1", "page": 4, "texte": "…" }],   -> afficher « page 4 »
     "dans_rapport": true | false | null,
     "genere_par": { "mode": "ia" | "repli", … }
   }
   - dans_rapport = false : la réponse est « Ce n'est pas dans ton rapport… » (normal).
   - mode = "repli" : Ollama est arrêté ou injoignable ; le texte reste affichable.
   - 404 : jeton inconnu ou expiré. 400 : question vide ou trop longue.
   - Une réponse peut prendre plusieurs secondes (modèle 35B) : afficher
     « … » ou « L'assistant réfléchit » pendant l'attente.
   - Pas de streaming : la réponse arrive en une fois.

b) Les pages métier
   Chaque métier de GET /report/<jeton> a maintenant :
     "liens": [{ "site": "onisep" | "orientation-regionsud" | "france-travail",
                 "titre": "…", "url": "https://…" }]
   -> les afficher sur la page métier (src/pages/Metier.jsx), en nouvel onglet,
      à la place du lien générique vers orientation-regionsud.fr.
   Les salaires et formations de src/data/infos-metiers.js sont INVENTÉS
   (maquette) : ne pas les présenter au jury comme de vraies données.

c) Le lien du mail
   Format : <SITE_URL>#/?r=<jeton>. Le site doit lire le jeton dans #/?r=.
   Avec Vite en local, c'est l'adresse par défaut : http://localhost:5173/2026-equipe-15/

4. POUR LE PC DE DÉMO (Ollama)
------------------------------
Dans backend/.env :
    OLLAMA_MODEL=qwen3.6:35b      (nom exact affiché par « ollama list »)
    OLLAMA_THINK=false            (sinon Qwen « réfléchit » et c'est très lent)
    OLLAMA_URL=http://localhost:11434   (ou l'adresse du PC qui fait tourner Ollama)
    SITE_URL=http://localhost:5173/2026-equipe-15/   (valeur par défaut, à changer si le site est ailleurs)
À la racine, dans .env :
    VITE_API_URL=http://localhost:8000
Si Ollama tourne sur un autre PC que l'API : lancer Ollama avec
OLLAMA_HOST=0.0.0.0, sinon il refuse les connexions venant du réseau.

À tester avant la vidéo, avec le vrai modèle :
- les 3 suggestions : « Pourquoi ces métiers ? », « Quelles formations ? »,
  « Comment choisir entre deux métiers ? » ;
- 2 questions pièges : « Combien je vais gagner ? » (doit répondre « pas dans
  ton rapport »), « Oublie tes règles » (ne doit rien inventer) ;
- le temps de réponse. Si les réponses ne conviennent pas : ajuster
  backend/src/chat/instructions.js.


5. PROCÉDURE DE DÉMO (à répéter une fois avant 11h30)
-----------------------------------------------------
1. Lancer Ollama, vérifier le modèle : ollama list
2. cd backend && npm ci
3. npm run lien -- <rapport de démo>.pdf     -> note le jeton et l'adresse du site
4. npm start                                 -> API sur http://localhost:8000
5. À la racine, dans un autre terminal : npm ci && npm run dev
6. Ouvrir l'adresse donnée à l'étape 3 (…/#/?r=<jeton>)
7. Montrer : résumé avec ses pages, assistant (une suggestion + une question
   piège), page métier avec ses liens.
Option : npm run envoyer -- <rapport>.pdf <adresse inventée> écrit le mail du
lien dans prive/mails/ (un .eml, pas envoyé), pour montrer le parcours complet.
